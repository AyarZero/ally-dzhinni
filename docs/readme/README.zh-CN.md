# AllY · 精灵 (v0.1)

面向 Windows 的本地桌面应用，将多个 AI 集成在同一窗口中，共享对话历史，并提供磁盘本地记忆、任务队列与额度监控。

*AllY · 精灵的生日是 2026 年 11 月 23 日。许可证：MIT。*

---

## 这是什么应用，解决什么问题

经常使用 AI 时，任务很快就会分散到不同的浏览器标签页、终端窗口和独立密钥中。当一个模型的 5 小时额度耗尽时，就得打开另一个模型，重新解释项目上下文。

**AllY · 精灵**解决四个实际问题：

- **模型之间共享上下文。** 对话历史和你的规则库以 Markdown 文件保存在本地（`pamyat/`）。可直接在输入栏切换 AI、模型或推理深度，让下一个模型从原处继续任务。
- **CLI 智能体的操作透明可见。** 在普通终端中，很难及时看到智能体当前执行的步骤并中途干预。AllY 左侧显示状态球和实时操作流，通过可拖动调宽的平滑垂直分隔线与右侧分开；右侧显示对话和任务队列，支持即时补充指令（`live-steer`）、编辑队列和优先处理重要消息。
- **监控额度和上下文窗口。** **“资源”**组件显示主力 AI、上下文占用情况（阈值为 `350k`），以及订阅的 5 小时和每周额度；**“助手”**标签页汇总其他连接的余额。这些指标在本地读取，不会产生付费的后台调用。
- **掌控数据，直连服务。** 对话、`pamyat/` 笔记、`.claude/skills/` 技能和 `.ally-data/` 本地设置均保留在你的电脑上。你直接使用所选服务商的个人订阅和密钥。

## 适用人群

- **开发者和氛围编程用户**：通过 Claude Code、Codex、Antigravity 或 DeepSeek 开发项目，希望在同一个可控窗口中查看智能体步骤、任务队列和上下文消耗。
- **创作者、创业者和专业人士**：需要在自己的电脑上为项目维护统一的本地记忆。
- **Windows 10/11 用户**：需要可按任务调整布局的本地工具，并希望通过内置反馈影响后续版本。

## 0.1 版本中已可用的功能

### 1. 连接与“自动”模式
至少配置一种连接即可开始使用。在**“自动”**模式下，系统会自行选择可用的执行引擎：

| 连接 | 工作方式 | v0.1 中的能力 |
|---|---|---|
| **Claude Code** | 使用 Anthropic Pro / Max 订阅的官方 CLI | 复杂任务、代码、文本、规划和上下文自动压缩 |
| **Codex** | 使用 ChatGPT Plus / Pro 订阅的官方 CLI | 处理代码仓库，并在回复过程中即时补充指令（`live-steer`） |
| **Antigravity** | Google AI 官方 CLI | 大上下文分析（窗口阈值 `350k`）和额度跟踪 |
| **DeepSeek Harness** | 使用 DeepSeek 余额的本地无界面配置 `dsh` | 备用且经济的执行引擎，可在“助手”标签页查看余额 |
| **API 聚合器（OpenRouter）** | 通过 Base URL 和密钥接入任意兼容 Anthropic 的网关 | 通过本地 Claude Code CLI 进程连接外部模型（无需 Anthropic 订阅） |
| **Qoder CLI** | 本地 CLI（检测与登录） | 连接向导可检测并支持在窗口内登录；作为对话主力引擎的功能将在下次更新推出 |

### 2. 工作区与界面
- **初始界面：**左侧为**“对话”**，带纯净状态球（球内无文字）、实时步骤流与平滑视差分隔线；右侧上方为**“资源” / “助手”**、下方为**“笔记本硬件”**，可在编辑模式下自由拖动边界调整大小。
- **顶部栏（从右到左）：**最右侧为时钟，依次为加宽版**反馈面板（小虫图标）**、**画笔**（拖动与调整组件大小、标签和图标顺序、重置布局）、**主题**（默认**石墨**，另含青绿、午夜、深色、浅色）、**书本图标（内置指南与版本历史）**，以及**闪电图标**（含全宽**“阅读模式”**的 3 步连接向导）。
- **本地存储：**`pamyat/`（Markdown 本地记忆）、`.claude/skills/`（本地技能）、`.ally-data/`（密钥和窗口布局，已从 Git 中排除）。

## 安装与启动（Windows 10/11）

**安装前，请确认系统已安装以下工具，并且可通过 `PATH` 访问：**
1. **Node.js 24+**（支持内置模块 `node:sqlite`）
2. **Python 3**
3. **Git**
4. 首次构建期间可访问互联网（用于 `npm ci` 和下载 Electron），并至少配置一个 AI 引擎或密钥。

任选以下三种安装方式：

### 方式 1 — 使用压缩包和熟悉的 `.exe`
1. 下载仓库的 ZIP 压缩包，解压到不含西里尔字母的短路径，例如 `C:\AllY`。
2. 双击 **`AllY.exe`**——首次启动会自动检查 `node` 24+、`python` 和 `git`，安装依赖，下载 Electron，构建可执行文件 **`programma\Dzhinni.exe`**，在桌面创建 **`AllY`** 快捷方式并打开应用窗口。
  *若 Windows SmartScreen 对未签名的新 `.exe` 弹出提示，点击「更多信息」→「仍要运行」（启动器源码公开在 `docs/launchers/`，也可直接运行 `.\ustanovka.ps1`）。*
3. 之后双击 **`AllY.exe`**、桌面上的 **`AllY`** 快捷方式，或直接运行 **`programma\Dzhinni.exe`** 即可启动。双击 **`AllY-Guide.exe`** 可在独立应用窗口中查看交互式文档与版本历史。
4. 首次启动会打开 3 步入门向导——连接所需的 AI，然后发送第一条消息。

### 方式 2 — 在终端中执行命令（PowerShell / cmd）
打开 PowerShell，依次执行：

```powershell
git clone https://github.com/AyarZero/ally-dzhinni.git C:\AllY
cd C:\AllY
.\AllY.exe
```

之后可用以下命令检查构建是否就绪：

```powershell
.\AllY.exe -Proverka
```

从终端启动：

```powershell
.\AllY.exe
```

### 方式 3 — 给本机 AI 助手的现成提示词
如果你的电脑上已经可以使用 Claude Code、Codex、Antigravity 或其他 AI 助手，请完整复制以下文本并发送给它：

```text
请从仓库 https://github.com/AyarZero/ally-dzhinni 在这台 Windows 电脑上安装本地桌面应用 AllY · 精灵 (v0.1)，并做好启动准备：
1. 在终端中检查是否有 `git`、`python`（Python 3）和 `node`（需要 Node.js 24+，且能通过 `node -e "require('node:sqlite')"` 检查）。如果缺少工具或 Node 版本低于 24，请告知我，并在构建前帮我补装。
2. 将仓库克隆到不含西里尔字母和空格的短路径，例如 `C:\AllY`，然后进入该文件夹。
3. 运行安装命令：`powershell -NoProfile -ExecutionPolicy Bypass -File .\ustanovka.ps1`，等待 `programma\Dzhinni.exe` 构建完成。
4. 使用命令 `powershell -NoProfile -ExecutionPolicy Bypass -File .\ustanovka.ps1 -Proverka` 检查构建。
5. 检查系统中已有的 CLI 引擎（Claude Code、Codex、Antigravity、DeepSeek Harness、Qoder）或 OpenRouter 密钥，并简要告诉我哪些已就绪。
6. 启动 `programma\Dzhinni.exe`（或 `.\AllY.exe`），并告诉我可以打开 AllY 窗口开始使用了。
```

*注意：已连接的 CLI 执行引擎会直接操作当前工作文件夹中的文件，不会在每次读取或修改时请求确认——请用 Git 管理重要项目。*

## 反馈与参与项目开发

顶部栏右侧（时钟左侧）有一个**小虫图标按钮——“反馈”**。你可以直接通过界面：

- 报告错误、界面故障或启动问题；
- 随消息附加最多 **3 个文件**作为依据：文本日志 `.txt` / `.md`（不超过 `2 MB`）、截图 `.png` / `.jpg` / `.jpeg` / `.webp` / `.gif`（不超过 `10 MB`），或短视频 `.mp4` / `.webm` / `.mov`（不超过 `25 MB`，附件总计不超过 `30 MB`）；
- 提议新模块、技能或使用场景。

发送的**仅限表单文本和你选择的文件**——对话、个人笔记和密钥仍保留在本地。开发者的回复会回到应用内的对话中。项目采用 MIT 许可证开放：你可以在 `.claude/skills/` 中创建自己的技能，也可以参与核心功能开发。

## v0.1 的已知问题和正在处理的限制

我们如实列出目前的限制和正在完善的部分：

1. **需提前安装环境依赖：**安装 `v0.1` 前，必须已安装 `Node.js 24+`、`Python 3` 和 `Git`——无需手动准备软件的一体化独立 `.exe` 安装程序仍在开发中。
2. **v0.1 客户端构建暂不显示语音输入和朗读功能：**本地语音识别（`GigaAM`）及其安装程序仍在完善，麦克风和语音按钮已暂时移除。
3. **日记（“坦诚对话”）在 v0.1 客户端版本中暂未开放：**正在完善多引擎支持，该标签页将在近期更新中上线。
4. **关闭窗口后，后台桥接服务延迟休眠：**关闭窗口后，如果立即重新打开另一个实例，本地桥接服务器可能要等空闲超时后才退出（最长约 9 分钟）。
5. **Qoder 正在集成中：**连接向导可以检测本地 Qoder CLI 和登录状态，但在下个版本发布前，暂不开放将 Qoder 用作对话主力引擎。
6. **反馈服务器的大附件接收功能正在更新：**如果在后端更新完成前，发送截图或视频时服务器返回文件大小超限或拒收错误，可立即改为仅发送文本，草稿不会丢失。
7. **平台：**目前仅针对 **Windows 10/11** 进行构建和测试。
