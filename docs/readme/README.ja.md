# AllY · ジンニー (v0.1)

複数のAIを1つのウィンドウにまとめるWindows向けローカルデスクトップシェル。会話履歴の共有、ディスク上のローカルメモリ、タスクキュー、利用上限の管理に対応します。

*AllY · ジンニーの誕生日は2026年11月23日です。ライセンス：MIT。*

---

## このアプリと解決する課題

AIを日常的に使うと、作業はブラウザーのタブ、コンソールウィンドウ、個別のキーに分散しがちです。あるモデルの5時間枠の利用上限に達すると、別のモデルを開き、プロジェクトの背景を最初から説明し直す必要があります。

**AllY · ジンニー**は、4つの実用的な課題を解決します。

- **モデル間でコンテキストを共有。** 会話履歴と独自のルール集は、ローカルのMarkdownファイル（`pamyat/`）に保存されます。入力欄からAI、モデル、推論の深さを切り替え、次のモデルが同じ地点から作業を引き継げます。
- **CLIエージェントの動作を可視化。** 通常のターミナルでは、エージェントの現在の処理を把握し、途中で介入するのは簡単ではありません。AllYでは、幅を調整できる滑らかな縦の境界線の左側に状態を示す球体と実行中の操作フィード、右側に会話とタスクキューを表示します。実行中の指示追加（`live-steer`）、キューの編集、重要なメッセージの優先処理に対応します。
- **利用上限とコンテキストウィンドウを管理。** **「リソース」**ウィジェットには、メインのAI、コンテキスト使用量（しきい値は`350k`）、サブスクリプションの5時間枠・週間枠が表示されます。**「アシスタント」**タブには、ほかの接続先の残高がまとまります。数値はローカルで取得し、有料のバックグラウンド呼び出しは行いません。
- **データの管理と直接接続。** 会話、`pamyat/`のメモ、`.claude/skills/`のスキル、`.ally-data/`のローカル設定は、自分のコンピューターに保存されます。自分のサブスクリプションとキーを使い、選んだプロバイダーに直接接続します。

## 対象ユーザー

- Claude Code、Codex、Antigravity、DeepSeekでプロジェクトを進め、エージェントの処理、キュー、コンテキスト消費を1つの操作可能なウィンドウで確認したい**開発者やバイブコーダー**。
- 自分のPC上で、プロジェクト用の共通ローカルメモリを使いたい**著述家、起業家、各分野の専門家**。
- 作業に合わせてレイアウトを調整でき、組み込みのフィードバック機能で今後のリリースに意見を届けられるローカルツールを求める**Windows 10/11ユーザー**。

## バージョン0.1で実際に動く機能

### 1. 接続と「自動」モード
少なくとも1つの接続先を設定すれば使い始められます。**「自動」**モードでは、利用可能な実行エンジンをシステムが選択します。

| 接続先 | 動作方式 | v0.1でできること |
|---|---|---|
| **Claude Code** | Anthropic Pro / Maxサブスクリプションの公式CLI | 複雑なタスク、コード、文章、計画、コンテキストの自動圧縮 |
| **Codex** | ChatGPT Plus / Proサブスクリプションの公式CLI | リポジトリでの作業と、回答生成中の指示追加（`live-steer`） |
| **Antigravity** | Google AIの公式CLI | 大規模コンテキストでの分析（ウィンドウのしきい値は`350k`）と利用枠の追跡 |
| **DeepSeek Harness** | DeepSeek残高を使用するローカルのヘッドレスプロファイル`dsh` | 予備の低コスト実行エンジン。「アシスタント」タブで残高を確認 |
| **APIアグリゲーター（OpenRouter）** | Base URLとキーを使用する任意のAnthropic互換ゲートウェイ | ローカルのClaude Code CLIプロセスを介して外部モデルに接続（Anthropicのサブスクリプションは不要） |
| **Qoder CLI** | ローカルCLI（検出とログイン） | 接続ウィザードで検出（ウィンドウ内からのログインを含む）。チャットのメインエンジンとしての利用は次回更新で対応予定 |

### 2. ワークスペースとインターフェース
- **起動画面：** 左側に文字なしの状態球体とステップ表示を持つ**「会話」**、右側に高さ調整可能な**「リソース」/「アシスタント」**（上）と**「ノートPC」**モニター（下）が配置されています。
- **上部バー（右から左へ）：** 右端の時計、ワイド表示の**フィードバックパネル（虫）**、**ブラシ**（ウィジェットの移動とサイズ変更、レイアウト初期化）、**テーマ**（既定は**グラファイト**、ほかにターコイズ・ミッドナイト・ダーク・ライト）、ウィンドウ内で開く**本アイコン（ガイド＆更新履歴）**、**稲妻**（全幅**「閲覧モード」**付き3ステップ接続ウィザード）。
- **ローカル保存：** `pamyat/`（ローカルMarkdownメモリ）、`.claude/skills/`（ローカルスキル）、`.ally-data/`（キーとウィンドウのレイアウト。Gitの管理対象外）。

## インストールと起動（Windows 10/11）

**インストール前に、以下がインストール済みで、`PATH`から利用できることを確認してください。**
1. **Node.js 24+**（組み込みモジュール`node:sqlite`に対応）
2. **Python 3**
3. **Git**
4. 初回ビルド時のインターネット接続（`npm ci`とElectronのダウンロード用）、および少なくとも1つの接続済みAIエンジンまたはキー。

次の3つの方法から選んでインストールできます。

### 方法1 — アーカイブと使い慣れた`.exe`
1. リポジトリのZIPアーカイブをダウンロードし、`C:\AllY`など、キリル文字を含まない短いパスに展開します。
2. **`AllY.exe`**をダブルクリックします。初回起動時は`node` 24+、`python`、`git`を確認し、依存関係のインストール、Electronのダウンロード、実行ファイル**`programma\Dzhinni.exe`**のビルド、デスクトップへの**`AllY`**ショートカット作成を行い、そのままアプリウィンドウを開きます。
  *未署名の新しい `.exe` に対し Windows SmartScreen の警告が出た場合は「詳細情報」→「実行」を押してください（ランチャーのソースは `docs/launchers/` に公開されており、`.\ustanovka.ps1` を直接実行することもできます）。*
3. 次回からは**`AllY.exe`**、デスクトップの**`AllY`**ショートカット、または**`programma\Dzhinni.exe`**をダブルクリックして起動します。ガイドと更新履歴を専用アプリウィンドウで開くには**`AllY-Guide.exe`**を実行してください。
4. 初回起動時は3ステップのセットアップウィザードが開きます。使用するAIを接続して、最初のメッセージを送信してください。

### 方法2 — ターミナルのコマンド（PowerShell / cmd）
PowerShellを開き、順に実行します。

```powershell
git clone https://github.com/AyarZero/ally-dzhinni.git C:\AllY
cd C:\AllY
.\AllY.exe
```

後からビルドの準備状況を確認するには、次を実行します。

```powershell
.\AllY.exe -Proverka
```

ターミナルから起動するには、次を実行します。

```powershell
.\AllY.exe
```

### 方法3 — ローカルAIに渡すインストール用プロンプト
コンピューター上でClaude Code、Codex、AntigravityなどのAIアシスタントをすでに使っている場合は、以下の全文をコピーして送信してください。

```text
このWindows PCに、リポジトリ https://github.com/AyarZero/ally-dzhinni からローカルデスクトップアプリAllY · ジンニー (v0.1) をインストールし、起動できる状態にしてください。
1. ターミナルで`git`、`python`（Python 3）、`node`の有無を確認してください。Node.js 24+が必要です。`node -e "require('node:sqlite')"`が正常に実行できることも確認してください。不足するものがある場合やNodeのバージョンが24未満の場合は、私に知らせ、ビルド前の追加インストールを手伝ってください。
2. リポジトリを`C:\AllY`など、キリル文字と空白を含まない短いパスにクローンし、そのフォルダーに移動してください。
3. `powershell -NoProfile -ExecutionPolicy Bypass -File .\ustanovka.ps1`でインストールを実行し、`programma\Dzhinni.exe`のビルド完了を待ってください。
4. `powershell -NoProfile -ExecutionPolicy Bypass -File .\ustanovka.ps1 -Proverka`でビルドを確認してください。
5. システムで利用できるCLIエンジン（Claude Code、Codex、Antigravity、DeepSeek Harness、Qoder）やOpenRouterのキーを確認し、何がすでに準備できているか簡潔に教えてください。
6. `programma\Dzhinni.exe`（または`.\AllY.exe`）を起動し、AllYのウィンドウを開いて作業を始められることを私に伝えてください。
```

*注意：接続したCLI実行エンジンは、開いている作業フォルダーのファイルを直接操作し、読み取りや編集のたびに確認を求めません。重要なプロジェクトはGitで管理してください。*

## フィードバックとプロジェクト開発への参加

ヘッダー右側（時計の左）には、**虫のアイコンの「フィードバック」**ボタンがあります。インターフェースから直接、次のことができます。

- バグ、インターフェースの不具合、起動の問題を報告する。
- 証拠となるファイルを最大**3ファイル**添付する。テキストログ`.txt` / `.md`（最大`2 MB`）、スクリーンショット`.png` / `.jpg` / `.jpeg` / `.webp` / `.gif`（最大`10 MB`）、短い動画`.mp4` / `.webm` / `.mov`（最大`25 MB`、添付全体で最大`30 MB`）に対応。
- 新しいモジュール、スキル、利用方法を提案する。

送信されるのは**フォームのテキストと自分で選んだファイルだけ**です。会話、個人メモ、キーはローカルに残ります。開発者からの返信は、アプリ内の会話に届きます。プロジェクトはMITライセンスで公開されています。`.claude/skills/`に独自のスキルを作成したり、コアの改善に参加したりできます。

## 現在対応中のv0.1の既知の問題と制限

現時点の制限や調整中の項目を、率直に記載します。

1. **実行環境の依存ソフトは事前インストールが必要：** `v0.1`のインストールには、`Node.js 24+`、`Python 3`、`Git`がインストール済みである必要があります。ソフトの手動準備が不要な単体の`.exe`インストーラーは開発中です。
2. **v0.1のクライアントビルドでは音声入力と読み上げを非表示：** ローカル音声認識（`GigaAM`）とそのインストーラーを調整しているため、マイクと音声のボタンを一時的に削除しています。
3. **日記（「率直な対話」）はv0.1クライアントビルドでは非表示です：** 複数エンジン対応を仕上げている段階であり、次期アップデートで公開予定です。
4. **ウィンドウを閉じた後、バックグラウンドブリッジの停止まで時間がかかる場合がある：** ウィンドウを閉じてすぐに別のインスタンスを開くと、ローカルのブリッジサーバーがアイドルタイムアウト（最大約9分）まで終了しない場合があります。
5. **Qoderは統合作業中：** 接続ウィザードはローカルのQoder CLIとログイン状態を検出しますが、会話のメインエンジンとしての利用は次回リリースまで無効です。
6. **フィードバックの大容量添付に対するサーバー側の受け入れ対応は段階的に更新中：** バックエンドの更新完了前にスクリーンショットや動画を送信し、サイズやファイル受け入れのエラーが返った場合は、下書きを失わず、そのままテキストのみで送信できます。
7. **プラットフォーム：** ビルドとテストは**Windows 10/11**のみで実施しています。
